## Executable delivery

`facet sync --once --yes` reuses production preview/start/cycle with a single
held writer. Without `--once`, it enters the existing foreground Dashboard/sync
loop after selecting the scope once. No new engine, journal, IPC, schema or
Compose default change. Missing role authorization, runtime input/confirmation,
stale preview and owner conflicts fail before historical start or target writes.
The shared credential preparation retains the previous two-role scope/profile,
refresh and ownership policy.

The no-key operation identity uses persisted namespace/binding/config/ruleset
and calendar-window inputs, not evolving thread generation totals. Explicit IDs
derive stable child keys independently of current rules/calendar; existing
preview/start records retain their selected scope after interruption/replay.
Plain run and continuous iterations do not select a new historical scope.
Public results contain aggregate cycle/disclosure information, not mail IDs,
accounts, rule values, raw provider errors or credentials.
